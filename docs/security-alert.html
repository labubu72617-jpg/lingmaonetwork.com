三、密码学基石：NIST SP 800-63B 与 k-Anonymity 零知识盲匹配模型

在资产泄露排查领域，用户面临的最大担忧往往是：“如果我把自己的邮箱或密码输入到检测系统里查询，这难道不会变成另一场针对我的数据收集与二次泄露吗？”

灵猫网络泄露预警在设计之初便确立了“零知识证明 (Zero-Knowledge Proof)”的底层数学准则，严格遵照 美国国家标准与技术研究院 NIST SP 800-63B 及 RFC 9162 标准，采用 k-Anonymity（k-匿名）盲比对模型：

📐 k-Anonymity 盲匹配数学原语流程：

  1. 客户端单向散列：当用户在自查界面输入待测凭证字符串 (S)（如邮箱或密码），浏览器前端在本地内存中即时计算其 SHA-256 完整散列：
    H = SHA-256(S) = [c1, c2, c3, ..., c64]
  2. 截取 5 位前缀桶标识 (Bucket ID)：客户端仅提取哈希值的前 5 个十六进制字符：
    Prefix = H[0..4] = [c1, c2, c3, c4, c5]（例如 8F4C2）
  3. 盲前缀出网查询：客户端向灵猫情报网关发起查询请求 GET /api/v2/threat-intel/pwned/8F4C2。请注意：原始明文 (S) 与完整哈希 (H) 绝不离开用户的本地浏览器！网络链路上仅能观察到极其普通的 5 个字符。由于 5 位十六进制前缀对应着 (16^{59}) 种极度庞大的可能性，任何监听者在数学上都不可能逆向推导出用户的真实信息。
  4. 服务端返回候选后缀集合：灵猫情报服务器在海量哈希索引中检索所有以 Prefix 开头的泄露哈希，将对应的数百至数千条“后缀部分”打包回传至用户浏览器。
  5. 客户端离线内存比对：浏览器在本地沙箱内存中将自身的完整哈希与返回的候选后缀逐一比对，若命中碰撞则提示泄露，否则证明安全。
